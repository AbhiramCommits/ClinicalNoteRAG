# ClinicalNoteRAG

## 1. What it is

ClinicalNoteRAG is a research system for **retrieval-augmented, citation-grounded
question answering over synthetic FHIR R4 bundles and synthetic clinical and
payment-operations notes**. It targets treatment, payment, and operations (TPO)
questions such as "what diagnoses were documented for this encounter", "why was
this claim denied and what supports an appeal", and "how many encounters did
this patient have". Every answer must either cite the retrieved evidence that
supports each sentence or explicitly abstain.

The system includes synthetic data generation, a PHI de-identification gate
with a leak audit, section-aware chunking, pluggable embeddings, FAISS and
pgvector stores behind one interface, hybrid dense/BM25 retrieval, a cited and
abstaining answerer, a post-hoc citation verifier, FastAPI serving, cost and
latency telemetry, a benchmark harness with 10,000-resample bootstrap CIs, a
LoRA/PEFT adapter training path, a fallback learned reranker, an Airflow-style
refresh DAG, Docker packaging, and dry-run SageMaker / Azure ML deployment
builders.

> **Research only. Not clinical advice, not a medical device, and not for real
> PHI.** All records are generated by code in this repository. No real patient
> data was downloaded or committed.

## 2. Architecture

```text
                    synthetic FHIR R4 + notes (code, seed 42)
                                   |
                                   v
             +-------------------------------------------+
             | 300 patients / 739 encounters / 1,478     |
             | clinical + payment notes (fake PHI)       |
             +---------------------+---------------------+
                                   |
                                   v
             +-------------------------------------------+
             | PHI de-identification                      |
             | Presidio (if importable) -> regex fallback|
             | typed [NAME_1] tokens; reversible maps     |
             | stored OUTSIDE the vector store            |
             +---------------------+---------------------+
                                   |
                                   v
             +-------------------------------------------+
             | section-aware chunker (256 tokens / 32    |
             | overlap) + one fact chunk per FHIR fact    |
             +---------------------+---------------------+
                                   |
                     +-------------+-------------+
                     |                           |
                     v                           v
       Sentence-Transformers MiniLM      deterministic hashing-TFIDF
       (384-d, if loadable)              (512-d, offline fallback)
                     +-------------+-------------+
                                   |
                                   v
             +-------------------------------------------+
             | FAISS IndexFlatIP + SQLite sidecar   OR   |
             | Postgres + pgvector (same interface)      |
             | metadata: patient, encounter, resource,   |
             | code system/code, date range, doc_type    |
             +---------------------+---------------------+
                                   |
                                   v
             +-------------------------------------------+
             | Hybrid retrieval: dense + BM25 -> RRF     |
             | optional metadata prefilter / reranker    |
             +---------------------+---------------------+
                                   |
                                   v
             +-------------------------------------------+
             | Grounded generator                        |
             | extractive (offline) | Qwen LoRA | OpenAI |
             | prompt requires [n] citations             |
             +---------------------+---------------------+
                                   |
                                   v
             +-------------------------------------------+
             | abstention gate + citation verifier       |
             | unsupported sentence -> flagged           |
             +---------------------+---------------------+
                                   |
                                   v
             FastAPI /ask, /ask/claims-denial, /healthz, /metrics
                                   |
                                   v
             JSONL cost/latency telemetry -> service metrics

 Refresh path (same functions, executed locally or by Airflow):
   generate_or_sync_corpus -> deid_scan -> chunk_and_embed -> upsert
     -> smoke_query -> publish_metrics

 Serving paths:
   local Docker -> FastAPI -> FAISS or pgvector
   AWS SageMaker spec (dry-run) / Azure ML managed endpoint (dry-run)
```

The Airflow DAG is `dags/clinical_embedding_refresh_dag.py`; it imports cleanly
without a scheduler. The same task functions run locally through
`scripts/run_refresh.py`.

## 3. How to run

### Setup

```bash
make setup
```

This creates `.venv` with Python 3.11 and installs the project plus dev and
ML extras. The console script is `clinicalnoterag`.

### Full pipeline

```bash
make gen            # 300 synthetic patients -> data/corpus
make deid-audit     # PHI leak audit -> artifacts/deid_audit.json
make ingest         # de-id, chunk, embed, upsert -> artifacts/ingest_report.json
make refresh        # same tasks as the Airflow DAG -> artifacts/refresh_metrics.json
make eval           # 235-item benchmark + 12-config ablation -> artifacts/eval/
make train          # SFT/LoRA attempt + fallback reranker + comparison
make smoke          # offline 20-patient end-to-end smoke (hashing + extractive)
make test           # pytest with coverage -> artifacts/coverage.json
make reproduce      # full end-to-end run from a clean generated-data state
```

### Serve

```bash
make serve                       # uvicorn on :8000
curl -s http://127.0.0.1:8000/healthz

curl -s -X POST http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{
    "question": "What diagnoses were documented for encounter ENC-0001-01?",
    "filters": {
      "patient_id": "PAT-0001",
      "encounter_id": "ENC-0001-01",
      "resource_type": "Condition",
      "doc_type": "fhir_fact"
    },
    "k": 5
  }'
```

If port 8000 is occupied, use `make serve PORT=8765` or
`scripts/smoke_queries.py --start-server --port 8765`. The API smoke command is
`make api-smoke`; it fires 102 real queries and writes
`artifacts/query_telemetry.jsonl` and `artifacts/service_metrics.json`.

### Docker and pgvector

```bash
docker compose up -d db
docker compose --profile pipeline run --rm ingest   # populate pgvector from data/corpus
docker compose up api
```

The API container uses `VECTOR_BACKEND=pgvector` and the pgvector service. If
the database is empty, `/ask` abstains rather than inventing an answer. The
pgvector store is exercised by the contract test suite against
`pgvector/pgvector:pg16` when Docker is available; otherwise those tests skip
with a recorded reason.

### Cloud deployment (dry run only)

```bash
python scripts/deploy/sagemaker_deploy.py --dry-run
python scripts/deploy/azureml_deploy.py --dry-run
```

Rendered manifests land in `artifacts/deploy/`. No cloud resources are created.
See `docs/cloud.md` for required IAM roles, Azure roles and environment
variables.

### Environment

Copy `.env.example` to `.env`. Important variables:

| Variable | Default | Notes |
| --- | --- | --- |
| `SEED` | `42` | Applied to Python/NumPy/PyTorch |
| `EMBEDDING_BACKEND` | `auto` | `auto` tries MiniLM then hashing |
| `LLM_BACKEND` | `auto` | `auto` uses extractive offline; `hf-local`/`openai` opt in |
| `VECTOR_BACKEND` | `faiss` | `faiss` or `pgvector` |
| `POSTGRES_DSN` | localhost:5433 | pgvector connection |
| `ARTIFACT_DIR` | `artifacts` | All measured outputs |
| `ABSTENTION_THRESHOLD` | `0.012` | Fused-score gate |
| `OPENAI_API_KEY` | empty | Commercial baseline only when set |

**Offline behavior.** `make smoke`, `make test`, `make lint`, the hashing
embedding backend, the regex de-identifier, the extractive generator and the
fallback reranker all run without network access. The main build used
`sentence-transformers/all-MiniLM-L6-v2`; its weights were downloaded once.
`HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` make the offline smoke path
explicit. Presidio is optional; when it is unavailable the engine records
`regex` as the backend that ran. The LoRA path needs the Qwen model weights;
if they cannot be loaded, the training log records the failure and the trained
fallback reranker remains the learned component.

## 5. Limitations and governance

- **Synthetic data only.** The corpus is generated by code, and the notes are
  templated. Results do not estimate performance on real clinical text,
  real coding distributions, or real payer policies.
- **Closed-world benchmark.** The 235 QA items are derived from the same FHIR
  bundles that populate the index. Recall@5 and exact match near 1.0 are an
  upper bound; the k=1 ablation shows how quickly evidence is lost when the
  retrieval budget is tight.
- **De-identification boundary.** The regex backend scored perfectly against
  the known injected strings and synthetic name gazetteer. That is not a
  real-world PHI guarantee. Reversible maps are written outside the vector
  store under `artifacts/deid_maps/` and are PHI-bearing by design; they must
  be access-controlled and never indexed or committed. Presidio did not run.
- **Extractive generation.** The selected main generator stitches retrieved
  facts and quotes; its zero hallucination rate is largely a property of that
  design. The LoRA adapter demonstrates that a 0.5B model trained for 12 steps
  does not automatically learn citation discipline (94.3% unsupported-claim
  rate).
- **No clinical validation.** No clinician reviewed the questions, answers,
  citation spans, or the appropriateness of the abstention policy.
- **No cost signal for commercial APIs.** The local cost model is $0 by
  construction; the commercial baseline was not run.
- **Operational gaps.** The Airflow scheduler was not run, pgvector was not
  load-tested at full corpus size, and cloud deployment was only rendered as a
  dry-run manifest. Telemetry is process-local JSONL, not a durable metrics
  backend.
- **Intended use:** research on grounded RAG, citation verification, abstention,
  synthetic clinical data engineering, and evaluation methodology.
- **Out of scope:** diagnosis, treatment recommendations, real claims
  adjudication, PHI processing, autonomous clinical or payment decisions, and
  any deployment without HIPAA/security/clinical governance review.
