# AI Governance: ClinicalNoteRAG

This document describes the risks of the ClinicalNoteRAG research system, the
controls implemented in code, the human-in-the-loop points, and the checklist
required before any release. It applies to the synthetic-data research
prototype only. Clinical or payment production use requires additional legal,
security, clinical, and regulatory review.

## 1. Scope and principles

- **Synthetic only.** All records are generated by repository code. No real PHI
  is downloaded, committed, indexed, or served.
- **Evidence over fluency.** Every answer must cite retrieved evidence or
  abstain. A plausible sentence without support is a defect.
- **Measure, don't assert.** Metrics come from artifacts produced by the
  commands in the README. Failed or unavailable components are recorded, not
  guessed.
- **Least data.** Reversible de-identification maps live outside the vector
  store and `artifacts/` is gitignored.
- **Human accountability.** The system is decision support for research, never
  an autonomous clinical, coverage, or payment decision-maker.

## 3. Controls implemented in code

### 3.1 De-identification audit gate

`clinicalnoterag.deid.audit.scan_corpus` re-scans every scrubbed note for the
injected PHI strings and returns `phi_leak_rate` plus per-entity recall. The
real build measured 0.000 leak on 1,478 documents with regex. The artifact is
written to `artifacts/deid_audit.json`; `make reproduce` regenerates it. A
release should block on a leak rate above the agreed threshold (the test suite
uses 0.005 as a smoke gate).

Reversible maps are written to `artifacts/deid_maps/` with an explicit
`"warning": "PHI-bearing reversal map. Never index or commit this file."`
`tests/test_ingest.py` asserts that the vector store contains no injected name
or MRN and that maps exist outside the store.

### 3.2 Citation verifier

`clinicalnoterag.rag.verify.verify_answer` splits the answer into sentences,
requires at least one citation marker per sentence, checks content-token
overlap against the cited chunk, and requires any codes in the sentence to
occur in that chunk. Failures set `unsupported_claim=True` and are exposed in
the API response, telemetry and evaluation artifacts. The verifier is a
deterministic NLI-lite check, not a learned entailment model; it is conservative
about fabricated codes and can miss omissions.

### 3.3 Abstention policy

`ClinicalAnswerer` abstains when:

- retrieval returns no chunks;
- the top fused score is below `ABSTENTION_THRESHOLD` (0.012);
- any hard identifier/code in the question is absent from the retrieved
  evidence; or
- the generator reports `Insufficient evidence`.

The abstention text is exactly "Insufficient evidence in the available record".
Adversarial items measure false answers; the baseline produced 0/40.

### 3.4 Metadata isolation tests

`tests/test_vectorstore.py` runs the same contract suite against FAISS and
pgvector, including the mandatory assertion that a patient filter never returns
another patient's chunks. `tests/test_retrieval_rag.py` also asserts no
cross-patient results from the live retriever. These tests must not be weakened.

### 3.5 Telemetry and metrics publication

`clinicalnoterag.telemetry` records per-query latency, abstention, confidence,
retrieved count, token counts, cost and unsupported-claim flag to JSONL.
`/metrics` computes p50/p95, abstention rate and mean cost from those events.
The Airflow-style DAG (`generate_or_sync_corpus → deid_scan → chunk_and_embed →
upsert → smoke_query → publish_metrics`) writes refresh metrics including
backend names, counts and task status. `scripts/run_refresh.py` executes the
same path locally.

### 3.6 Evaluation before selection

The evaluation harness reports Recall@k, MRR, exact match, token F1, numeric and
code-aware accuracy, hallucination/unsupported rate, false-answer rate,
abstention precision/recall and code P/R/F1 with 10,000-resample bootstrap CIs.
The multi-system comparison uses a patient-disjoint test split and paired
bootstrap deltas. The LoRA adapter is not selected if it fails citation and
abstention gates; in this build it produced 94.3% unsupported answers and was
reported separately.

## 4. Human-in-the-loop points

1. **Question design and benchmark review:** clinicians/coders review a sample
   of questions, gold answers and supporting chunks before evaluation is used
   for a decision.
2. **Citation spot checks:** reviewers inspect sampled answers and quote spans
   for clinical plausibility and correct source attribution.
3. **Abstention policy sign-off:** clinical and compliance owners approve the
   threshold and the exact abstention text before any user-facing deployment.
4. **De-identification review:** privacy/security reviews the backend selection,
   map storage, access control and audit results. Presidio must be loaded and
   tested before real-data use.
5. **Release approval:** a named accountable owner reviews the evaluation
   artifact, model card, governance checklist and rollback plan.
6. **Incident response:** unsupported claims, cross-patient leakage, PHI
   exposure or anomalous cost alerts page the on-call owner and trigger
   rollback.

## 5. Evaluation-before-release checklist

- [ ] All data confirmed synthetic; no real PHI in repo, images, caches or logs.
- [ ] De-id backend name and version recorded; leak audit below threshold;
      maps access-controlled and outside the index.
- [ ] Ingest report records embedding backend, dimension, store backend, chunk
      counts and wall time.
- [ ] Retrieval metrics (Recall@k, MRR) and answer metrics (exact, token F1,
      numeric/code accuracy) reported with 95% CIs.
- [ ] Hallucination/unsupported-sentence rate measured on answerable items.
- [ ] False-answer rate and abstention precision/recall measured on
      unanswerable items.
- [ ] Code extraction micro/macro P/R/F1 measured.
- [ ] k and retrieval-mode ablations run; selected k justified.
- [ ] Patient-disjoint split asserted; no test patient in training.
- [ ] Multi-system comparison includes no-RAG, zero-shot RAG and tuned; paired
      deltas with CIs and p-values; unavailable systems marked not run.
- [ ] LoRA/reranker selected only after passing citation and abstention gates;
      training path and exact config recorded.
- [ ] `make lint`, `make test` (with coverage artifact) and `make smoke` pass.
- [ ] pgvector contract tests either pass or skip with a recorded reason.
- [ ] API `/healthz`, `/ask`, `/ask/claims-denial`, `/metrics` tested; telemetry
      confirms latency, abstention and cost.
- [ ] DAG imports cleanly; refresh runner completes and publishes metrics.
- [ ] Docker image runs as non-root; no credentials baked in.
- [ ] Cloud deployment remains dry-run unless security/legal approval and IAM
      review are complete.
- [ ] README, research report and model card contain only artifact-backed
      numbers and state explicitly what did not run.
- [ ] Rollback plan and data/index version recorded.

## 6. Release decision

A release is **not approved** if any of the following is true: real PHI is
present, the de-id audit fails, citation verification is disabled, abstention
falls below the agreed threshold, patient-isolation tests fail, the evaluation
artifact is missing, or the system is presented as a clinical decision-maker
without regulatory review. The current repository is a research artifact, not
an approved clinical product.
