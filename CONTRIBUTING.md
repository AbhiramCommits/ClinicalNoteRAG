# Contributing

ClinicalNoteRAG is a synthetic-data research project. Contributions must keep
it safe to run offline and must not introduce real patient data.

## Ground rules

- **No real PHI.** Do not add real clinical records, MRNs, names, addresses, or
  scraped patient text. The corpus and notes are generated by
  `clinicalnoterag.data.synthea_gen` and `clinicalnoterag.data.notes_gen`.
- **Record the backend.** Any model-backed component needs a deterministic
  offline fallback and must surface the backend that actually ran in its result
  artifact. Never hard-code a metric.
- **Do not fabricate numbers.** If a step cannot run, write that down in the
  README/report rather than filling in a plausible value.
- **Seed everything.** Use seed 42 (`clinicalnoterag.seeds`) and the fixed
  bootstrap seed.

## Development setup

```bash
make setup          # creates .venv and installs .[dev,ml]
make lint
make test
make smoke          # offline 20-patient end-to-end check
```

Useful targets: `make gen`, `make deid-audit`, `make ingest`, `make refresh`,
`make eval`, `make train`, `make compare`, `make api-smoke`, `make reproduce`.

## Before opening a pull request

1. `make lint` passes (`ruff check .` and `ruff format --check .`).
2. `make test` passes with coverage; the pgvector contract tests run when
   Docker/Postgres is available and skip with a recorded reason otherwise.
3. If you change retrieval, generation, de-identification or the benchmark,
   re-run the relevant evaluation and update the measured results section.
4. Add a test for behaviour changes. The patient-isolation test in
   `tests/test_vectorstore.py` is mandatory; never weaken it.
5. Keep the DAG file importable without a scheduler:
   `python -c "import dags.clinical_embedding_refresh_dag"`.

## Code style

- Python 3.11, type hints on public functions, docstrings on public APIs.
- `ruff` is the formatter and linter; configuration lives in `pyproject.toml`.
- Prefer small, pure functions for benchmark and metric logic so they remain
  easy to test with hand-computed fixtures.

## Reporting issues

Include the command, Python version, backend selection, and the relevant
artifact path. Do not attach real patient data.
